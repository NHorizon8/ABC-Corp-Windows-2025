
ABC Corp के Active Directory domain में हमने पहले ही Default Domain Password Policy configure की है। यह domain users के लिए password और account lockout की सामान्य आधारभूत आवश्यकताएँ तय करती है। लेकिन संगठन में हर role की security requirements एक जैसी नहीं होतीं। उदाहरण के लिए, सामान्य कर्मचारी, IT administrator और service account के लिए अलग-अलग password controls की आवश्यकता हो सकती है। हर department के लिए अलग domain बनाने के बजाय, Active Directory में Fine-Grained Password Policies (FGPP) की मदद से एक ही domain के भीतर चुने हुए users या security groups पर अलग password और account lockout rules लागू किए जा सकते हैं।

Default Domain Password Policy पूरे domain के लिए baseline प्रदान करती है, जबकि FGPP विशेष users या groups के लिए अलग policy निर्धारित करने की सुविधा देती है। इन policies में minimum password length, password history, complexity requirements, maximum password age, account lockout threshold, lockout duration और failed-logon counter reset time जैसी settings शामिल हो सकती हैं। FGPP, Default Domain Password Policy को हर user के लिए replace नहीं करती; यह उन identities के लिए अतिरिक्त विकल्प देती है जिन्हें अलग rules चाहिए।

मान लो ABC Corp के IT department में पाँच users हैं। चार सामान्य IT assistants हैं और पाँचवाँ IT department का head है। हम assistants को एक security group और department head को दूसरे privileged group में रख सकते हैं। फिर दोनों groups के लिए अलग Password Settings Objects (PSOs बनाए जा सकते हैं। यदि IT head दोनों groups का member है, तो Active Directory को तय करना होगा कि उसके लिए कौन-सी policy प्रभावी होगी। इसी समस्या को समझने के लिए precedence mechanism उपयोग किया जाता है।

PSO और Password Settings Container (PSC) का काम अलग-अलग है। **Password Settings Object (PSO)** में वास्तविक password और account lockout rules होते हैं। **Password Settings Container (PSC)** Active Directory का वह system container है जहाँ PSOs store होते हैं। Container अपने आप किसी user पर policy लागू नहीं करता। PSO को किसी eligible user या security group के लिए assign किया जाता है, और Active Directory resultant policy निर्धारित करती है। एक ही PSO को कई users या groups पर लागू किया जा सकता है, इसलिए समान rules के लिए बार-बार नई policy बनाने की जरूरत नहीं होती।

FGPP को Active Directory Administrative Center (ADAC) के माध्यम से manage किया जाता है। PSO कोई सामान्य Group Policy Object (GPO) नहीं है, इसलिए इसे conventional Group Policy Management Console में GPO की तरह configure नहीं किया जाता। Container तक पहुँचने के लिए Active Directory Users and Computers में Advanced Features enable करके System container खोला जा सकता है। ADAC में इसके लिए System → Password Settings Container पर जाएँ।

हर PSO में numeric **Precedence** value होती है। जब किसी user पर group membership के माध्यम से एक से अधिक PSOs लागू हो सकती हैं, तो सबसे कम numerical precedence value वाली PSO प्रभावी होती है। उदाहरण के लिए, precedence `9`, precedence `10` से अधिक priority रखती है। बड़ा number अधिक priority नहीं दर्शाता।

ABC Corp के उदाहरण में, मान लो IT group की PSO की precedence `10` है और department-head group की PSO की precedence `9` है। यदि IT head दोनों groups का member है और दोनों PSOs group membership के माध्यम से लागू हो रही हैं, तो precedence `9` वाली department-head policy प्रभावी होगी। यदि किसी user को PSO सीधे assign की गई है, तो direct assignment, group-assigned PSOs पर प्राथमिकता रखती है। इसलिए conflict resolve करते समय assignment का प्रकार और precedence दोनों समझना जरूरी है। लागू FGPP, उस user के लिए Default Domain Password Policy से प्राथमिकता रखती है।

हम इस precedence वाले उदाहरण को concept के रूप में समझेंगे; इसे demonstrate करने के लिए lab में अतिरिक्त management groups और competing PSOs बनाना आवश्यक नहीं है। Hands-on अभ्यास में हम एक IT administrator group और account बनाएँगे, उस group के लिए एक PSO configure करेंगे, और resultant password settings verify करेंगे।

## ABC Corp — Hands-on Configuration

इस अभ्यास के लिए नीचे दिए गए नाम प्रस्तावित हैं। इन्हें पहले से मौजूद objects न मानें।

- **Target OU:** IT
- **Security group:** `GG_IT_Admins`
- **Example user:** `it.admin`
- **PSO name:** `FGPP-IT-Admins`
- **Precedence:** `10`

हमारा उद्देश्य IT administrator group पर अधिक सख्त password policy लागू करना है, बिना सभी domain users की baseline policy बदले।

ABC-DC01 पर Active Directory Users and Computers खोलें और IT organizational unit पर जाएँ। वहाँ `GG_IT_Admins` नाम का नया group बनाएँ। Group scope **Global** और group type **Security** चुनें।

### Step 5 — PSO को security group पर assign करें

## अंतिम समझ

Default Domain Password Policy baseline तय करती है। FGPP के माध्यम से हम एक PSO बनाकर चुने हुए users या security groups पर अलग password और account lockout rules लागू कर सकते हैं। PSC इन PSOs को store करता है, जबकि assignment और resultant-policy resolution तय करते हैं कि user पर कौन-सी policy प्रभावी होगी। जब कई group-assigned PSOs के बीच conflict होता है, तो सबसे कम numerical precedence value वाली PSO प्रभावी होती है; direct assignment, group-assigned PSOs पर प्राथमिकता रखती है।

हमारी ABC Corp lab में हम एक IT administrator security group, एक example user और एक PSO बनाएँगे। फिर ADAC में resultant password settings verify करेंगे। इससे हम पूरा workflow सीखेंगे, बिना lab को अनावश्यक रूप से अतिरिक्त departments, management groups या competing policies तक बढ़ाए।
